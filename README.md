# Генератор договоров

Статическое веб-приложение: менеджер заполняет форму → получает готовый Word-договор и PDF.
Работает целиком в браузере (в том числе на телефоне), сервер не нужен — публикуется на GitHub Pages.

## Как опубликовать

1. Создайте репозиторий на GitHub и загрузите в него содержимое этой папки.
2. Settings → Pages → Source: `Deploy from a branch`, ветка `main`, папка `/ (root)`.
3. Через минуту сайт будет доступен по адресу `https://<логин>.github.io/<репозиторий>/`.
4. Пришлите эту ссылку сотрудникам. Пароль входа — `2507`.

## Важно про безопасность

Сайт на GitHub Pages публичен по ссылке, даже если репозиторий приватный.
Пароль `2507` лежит в файле `js/app.js` в открытом виде и виден через «Просмотр кода» —
это фильтр от случайных людей, а не защита. Файл `templates/master_template.docx`
с банковскими реквизитами ИП скачивается по прямой ссылке кем угодно, кто знает адрес сайта.
Это осознанное решение заказчика.

## Как это работает

| Шаг | Чем делается |
|---|---|
| Заполнение Word по шаблону | `docxtemplater` + `pizzip` прямо в браузере |
| Вырезание разделов неактивных услуг | условные секции `{{#TAG}}...{{/TAG}}` того же docxtemplater |
| Предпросмотр | `docx-preview` рендерит **уже собранный** .docx в HTML |
| PDF | окно печати браузера по этому предпросмотру («Сохранить как PDF») |

PDF получается печатью предпросмотра, а не конвертацией Word. Вёрстка совпадает,
но колонтитул «стр. X из Y» в PDF не попадает — это поле Word, браузер номера страниц
не пересчитывает. Word-файл всегда точный.

## Проверка перед публикацией

```bash
perl build/serve.pl 8765 .
```

Затем откройте `http://127.0.0.1:8765/build/test.html` — прогон всех 20 сочетаний услуг.
Все строки должны быть зелёными. Открывать через `file://` нельзя: браузер заблокирует
загрузку шаблона и конфигов.

## Структура

```
index.html                    вход по паролю + форма + предпросмотр
css/style.css                 интерфейс
css/print.css                 печатная вёрстка (только предпросмотр)
js/numberToWords.js           сумма прописью со склонением
js/pricing.js                 стоимость и сроки по тарифной сетке
js/combinations.js            проверка 20 допустимых сочетаний услуг
js/numbering.js               сквозная нумерация этапов и перекрёстные ссылки
js/contract.js                сборка данных + рендер .docx
js/app.js                     UI, валидация, скачивание
config/services.json          тарифы и единицы измерения
config/term-rules.json        тарифные сетки сроков
config/combinations.json      20 допустимых сочетаний услуг
templates/master_template.docx мастер-шаблон договора
vendor/                       библиотеки (не с CDN — лежат в репозитории)
build/                        скрипты пересборки шаблона (в публикации не участвуют)
```

## Как поменять тарифы

Отредактируйте `config/services.json` (цены) и `config/term-rules.json` (сроки) —
код трогать не нужно, изменения подхватятся при следующей загрузке страницы.

## Как пересобрать шаблон

Исходник заказчика — `build/source.docx`. Скрипты `build/build_template.pl` и
`build/repack.ps1` заново собирают `templates/master_template.docx`:
склеивают плейсхолдеры, разорванные Word на несколько фрагментов, заменяют статичные
номера этапов на плейсхолдеры и выносят теги секций в отдельные абзацы.
`build/verify.pl` проверяет, что при этом не потерян ни один символ договора.

```bash
sh build/rebuild.sh
```

После **любой** правки шаблона обязательно прогоняйте все 20 сочетаний услуг:
сломанный тег секции проявляется только на той комбинации, где он используется.
